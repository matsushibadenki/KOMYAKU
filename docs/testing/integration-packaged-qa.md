## Reproduce

From `apps/desktop`, run `bun run test:integration:package`. Launch `src-tauri/target/debug/bundle/macos/KOMYAKU Integration QA.app` on an unlocked Mac. A fresh isolated profile should display `saved-all-bytes-verified`; later full process restarts should display `recovered-all-bytes-verified`. Any partial or unexpected existing fixture fails closed instead of being reset.

The QA database is `~/Library/Application Support/app.komyaku.desktop.integration-qa/komyaku.db`. Inspect it read-only. Do not remove a normal product profile or reset an existing QA profile to make a failing recovery pass. The runner contains fixed fixture IDs and timestamps; changing its fixture requires a separately named QA profile or an explicit migration/testing decision.

For response-loss verification, run `bun run test:integration-retry:package` from `apps/desktop` and launch `KOMYAKU Integration Retry QA.app`. This mode requires its own exact identifier before profile access, including when invoked through a query parameter. Its database is `~/Library/Application Support/app.komyaku.desktop.integration-retry-qa/komyaku.db`. First launch injects response loss; later launches only verify recovery without writes. Existing partial profiles fail closed.
